# Карточки CySEC / CIF для Валерии

Мобильное приложение для подготовки к экзамену: выбор темы, случайный порядок
карточек, проверка ответа и объяснение. Неверный ответ возвращает карточку в конец
очереди; правильный убирает её из занятия. После завершения можно повторить ту же
тему в новом порядке или выбрать другую. Прогресс хранится только в текущем занятии.

**Открыть:** https://jevgenijostin.github.io/cysec-flashcards/

Интерфейс и темы — на русском; вопросы, варианты и объяснения сохранены на
английском из PDF. Приложение не пересматривает содержание учебного источника.
HTML, CSS и JavaScript без сборки, внешних зависимостей, CDN и загружаемых шрифтов.

## Локальный запуск

Из корня репозитория: `python -m http.server 8000`, затем открыть
http://localhost:8000. Нужен HTTP-сервер, поскольку приложение загружает JSON через
`fetch`; открытие `index.html` как `file://` не подходит. Python нужен только для
локального сервера и извлечения, GitHub Pages обслуживает обычные статические файлы.

## Обновление карточек

Источник данных приложения — `data/cards.json`, массив объектов:

```json
{
  "id": 56,
  "topic": "Работа с клиентами и наилучшее исполнение",
  "question": "Точный текст вопроса из найденного источника",
  "options": ["Вариант A", "Вариант B", "Вариант C", "Вариант D"],
  "correctIndex": 0,
  "explanation": "Точное объяснение из источника"
}
```

Это пример структуры, не восстановленная карточка. `correctIndex` — индекс от 0
до 3 (A–D); `id` должен быть уникальным положительным целым числом. Вариантов ровно
четыре. Выбирайте тему по основному предмету вопроса, а не по словам в неверных
ответах; используйте точное существующее название темы. Схема распределения
текущего PDF находится в `topic_for` в `extract_cards.py`.

Когда Валерия найдёт полный источник, **просто добавьте** в массив объекты с `id`
**56, 57, 109–111, 121–123, 187–189**, заполнив реальные вопросы, ответы и объяснения.
Ожидаемые темы: 56–57 — работа с клиентами; 109–111 — AML/CDD; 121–123 — рыночная
инфраструктура; 187–189 — злоупотребления на рынке. Уточните тему по фактическому
содержанию найденной карточки. Порядок объектов не важен, не перенумеровывайте
существующие карточки. **Изменения кода не нужны**: темы, счётчики и очередь
строятся из JSON автоматически. Обновите таблицу и описание полноты в README.

Для повторного извлечения именно текущего неполного PDF:

```sh
python -m pip install PyMuPDF
python extract_cards.py
```

Скрипт проверяет 190 реальных номеров, четыре варианта и совпадение правильного
ответа. Известные отсутствующие номера пропускаются; фрагменты на границах пробелов
отбрасываются по границам страниц. Он перезаписывает JSON: после ручного добавления
найденных карточек используйте `--output extracted-cards.json` для сравнения,
чтобы не потерять дополнения. Для другого PDF правила границ нужно пересмотреть.

`audit_pdf.py` и `extraction-audit.json` — историческая диагностика исходника;
аудит требует 201 карточку и потому возвращает код 1 для этого PDF. Это не
проверка готовности приложения. Актуальное решение описано в EXTRACTION_REPORT.md.

## Публикация и проверка

GitHub Pages: ветка `main`, корень `/`. Изменения публикуются прямым push в `main`.
После редактирования JSON проверьте приложение локально и выполните:

```sh
git add .
git commit -m "Update flashcards"
git push origin main
```

Для браузерной проверки (только разработка): `pip install playwright`,
`python -m playwright install chromium`, запустить локальный сервер и выполнить
`python test_app.py`. Проверяются все 190 карточек, очередь ошибок, завершение,
повтор, выбор темы, мобильная ширина и ошибка загрузки.
